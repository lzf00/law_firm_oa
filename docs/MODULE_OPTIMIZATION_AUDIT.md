# 律所 OA 模块商业化审计与迭代台账

更新日期：2026-07-29

## 审计口径

本台账覆盖左侧导航的 19 个业务入口，同时检查页面主路径、后端能力、权限边界、双语、移动端与可验收性。状态含义：

- `可用`：主要业务闭环存在，已纳入全页面回归。
- `增强中`：核心闭环可用，但商业化体验或管理动作仍需补强。
- `管理完成`：管理员可在界面完成配置，后端有权限校验与审计。

## 管理后台权限模型

管理员后台采用“用户 - 角色 - 权限 - 办公室范围”四层模型：

1. 用户层：启用/停用、角色分配、临时访问截止时间。
2. 角色层：集中维护权限集合；系统管理员的控制台、用户、角色和审计关键权限受保护。
3. 权限层：前端只展示有权入口，路由二次校验；后端仍是最终授权边界。
4. 数据范围层：按办公室控制用户可见数据，避免仅靠角色造成跨办公室越权。

关键管理权限：

| 权限 | 用途 |
|---|---|
| `ADMIN_CONSOLE_VIEW` | 查看管理控制台 |
| `USER_ACCESS_MANAGE` | 管理账号状态、角色与办公室范围 |
| `ROLE_PERMISSION_MANAGE` | 调整角色权限 |
| `SETTINGS_MANAGE` | 管理组织级系统设置 |
| `WORKFLOW_RULE_MANAGE` | 管理工作流规则 |
| `AUDIT_VIEW` | 查看安全审计日志 |

## 本阶段验收基线

- 后端：隔离的全新 PostgreSQL/Redis/MinIO 环境完成所有迁移，98 个 Maven 测试通过。
- 管理 API：权限目录、角色列表、用户列表、管理员关键权限保护、非法权限拒绝、普通用户拒绝、审计留痕全部通过。
- 前端：12 个单元测试和生产构建通过。
- 全模块：桌面中文、桌面英文、移动中文覆盖 19 个入口，3 组 Playwright 用例通过；无严重可访问性问题、横向页面溢出、控制台错误或 5xx。
- 管理后台视觉：人员、角色、权限弹窗、系统设置、安全审计及移动端布局通过；页面级横向溢出为零。

## 后续迭代顺序

1. P0：文档中心和文档治理的版本、预览、授权、治理管理闭环。
2. P0：财务与计费写入闭环，以及报销附件和财务复核。
3. P0：利益冲突结论留痕和合同版本/签署文件闭环。
4. P1：审批模板、任务看板、日历提醒、组织与办公室增强。
5. P1：自定义角色发布审批、权限变更 diff、管理员操作二次确认。

每项完成后必须重复：单元测试、API 权限正反例、桌面/移动/中英视觉回归、全新数据库迁移验证和生产只读验收。
